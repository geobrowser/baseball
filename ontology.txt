================================================================================
RETROSHEET x GEO — ONTOLOGY DESIGN DOCUMENT
================================================================================

Models 14 parsed Retrosheet datasets (~16.3M records, 9.6 GB) as a Geo
knowledge graph using GRC-20 conventions. Three kinds of types:

  • Top-level entity types        — browseable, page-style nodes
  • Relation entity types          — entities that act as a link, with
                                     their own schema of properties
  • Reference / lookup types       — small finite sets pointed to by
                                     relation properties (positions,
                                     handedness, weather codes, etc.)


================================================================================
TABLE OF CONTENTS
================================================================================

  1. Naming conventions
  2. Top-level entity types
       Person · Team · Ballpark · City · State or region · Country ·
       League · Game · Season · Roster entry · Staff stint ·
       Batting line · Pitching line · Fielding line · Play · Ejection ·
       Scheduled game · Notable game collection
  3. Relation entity types
       Team game record · Umpire assignment ·
       Roster position assignment · Team ballpark tenancy
  4. Reference / lookup types
       (19 ref types: Position, Handedness, Person role, Game type, …)
  5. Relation summary (which relation property connects what to what)
  6. Entity relationship diagram (ASCII)


================================================================================
1. NAMING CONVENTIONS
================================================================================

Applied to all type names, property names, and reference instance names.

  1. Only the first letter of the first word is capitalized, unless the
     word is an acronym (RBI, ERA, MLB, ID, OPS, WHIP, DH, PBP, ISO,
     DNP, etc.).
       ✓  "Hit by pitch", "Home runs", "Runs batted in", "Hall of fame"
       ✗  "Hit By Pitch", "Hall Of Fame"

  2. Minor words (prepositions, articles) stay lowercase mid-name.
       ✓  "Runner on 1B", "Top of inning", "Reached on error",
           "Grounded into double play", "Pitcher responsible for runner
           on first"

  3. Parenthetical units are lowercase.
       ✓  "Height (inches)", "Weight (lbs)", "Duration (minutes)",
           "Innings pitched (outs)", "Temperature (F)", "Wind speed (mph)"

  4. Boolean properties:
       • Official-stat style (no "Is" prefix):
           Day game, Game started, Complete game, Save, Loss,
           No outs recorded, Started at position, Used DH, Hall of fame
       • State-description style ("Is" prefix):
           Is plate appearance, Is at bat, Is designated hitter


================================================================================
2. TOP-LEVEL ENTITY TYPES
================================================================================

Properties are listed as: Property name | Data type | Description | Source.
"System" in the Source column means a GRC-20 system property (Name,
Description, Cover, Avatar) that every entity may carry.


-- Person --

Description:
  A person in baseball history — player, manager, coach, umpire, or
  official scorer. One Person per individual; multiple roles across a
  career are inferable from Roster entry and Staff stint membership.

Source: players.json
Name format:  full common name (e.g., "Shohei Ohtani")
Description format:  e.g., "Two-way player. Bats L / Throws R. Active
  2018–present."

Properties:
  Name                       | Text          | Common full name           | players.full_name (fallback to first_name + last_name)
  Description                | Text          | Short blurb                | system
  Cover                      | Image         | Banner image               | system
  Avatar                     | Image         | Headshot                   | system
  Also known as              | Text (multi)  | Birth name / AKA           | players.birth_name, players.alt_name (when ≠ Name)
  Birth date                 | Date          | ISO date                   | players.birth_date
  Birth place                | Relation →    | City, else State or region | players.birth_city / birth_state / birth_country
                             | City | State  | else Country               | (link to most-specific known)
                             | or region |   |                            |
                             | Country       |                            |
  Death date                 | Date          | Null if alive              | players.death_date
  Death place                | Relation →    | Same multi-target rule     | players.death_city / death_state / death_country
                             | City | State  | as Birth place             |
                             | or region |   |                            |
                             | Country       |                            |
  Bats                       | Relation →    | Batting hand               | players.bats (L/R/B/?)
                             | Handedness    |                            |
  Throws                     | Relation →    | Throwing hand              | players.throws
                             | Handedness    |                            |
  Height (inches)            | Integer       | Whole inches               | players.height_inches
  Weight (lbs)               | Integer       | Whole pounds               | players.weight_lbs
  Hall of fame               | Boolean       | Inducted into MLB HOF      | players.hall_of_fame
  Retrosheet person ID       | Text          | e.g., "ohtas001"           | players.retrosheet_id


-- Team --

Description:
  A baseball franchise across its history. One entity per franchise (not
  per season); season membership is captured by Roster entry / Staff
  stint and Game participation.

Source: teams.json
Name format:  full team name "{city} {nickname}" (e.g., "New York Yankees")

Properties:
  Name                       | Text          | Full team name             | teams.full_name
  Description                | Text          | League + active years      | system
  Cover                      | Image         | Banner                     | system
  Avatar                     | Image         | Logo                       | system
  Also known as              | Text (multi)  | Historical alternate names | derived
  City                       | Relation →    | Home city                  | teams.city (deduped → City entity)
                             | City          |                            |
  Leagues                    | Relation →    | All leagues this franchise | teams.league (split on ";"
                             | League (multi)| has played in              | for compound values like "NL;AL")
  First active year          | Integer       | First active season        | teams.first_year
  Last active year           | Integer       | Last active season         | teams.last_year (null if active)
  Home ballparks             | Relation →    | All venues used as home,   | derived from gamelogs (group by
                             | Ballpark      | with tenancy windows on    | home_team + park_id, min/max date);
                             | (multi,       | the relation entity        | relation entity = Team ballpark
                             | ordered)      |                            | tenancy
  Retrosheet team ID         | Text          | e.g., "NYA"                | teams.retrosheet_id
  Alternate Retrosheet IDs   | Text (multi)  | Other codes used by team   | teams.alt_ids

Notes:
  • 77 of 293 teams have an empty league field (mostly defunct early
    leagues) — skip the Leagues relation rather than using a placeholder.
  • Houston Astros (NL → AL in 2013) and many Negro League teams have
    multiple leagues — Leagues is intentionally multi-valued.

3. RELATION ENTITY TYPES

Entities that *are* the link between two other entities, with their own

entity" type; the relation entity carries any per-link data.

-- Roster position assignment --

Used on:    Roster entry."Positions played" relation
Connects:   Roster entry → Position
Cardinality: one per position the player appeared at
Source:     rosters.position (primary) + allplayers g_p / g_sp / g_rp /
            g_c / g_1b / g_2b / g_3b / g_ss / g_lf / g_cf / g_rf / g_of /

Games played.


-- Team ballpark tenancy --

Used on:    Team."Home ballparks" relation
Connects:   Team → Ballpark
Cardinality: one per (Team, Ballpark) combination
Source:     derived from gamelogs (filter to home games for this team,
            group by park_id, min/max date)

Description:
  When a team played its home games at a given ballpark — useful for
  teams that switched parks (Yankees: Yankee Stadium I → temp digs →
  Yankee Stadium II) or shared parks during transitional periods.

Properties:
  First game date            | Date  | First home game at this park   | derived
  Last game date             | Date  | Last home game at this park    | derived
  Notes                      | Text  | e.g., "shared with BSN 1914-15"| derived

Ordering: chronological by First game date.
