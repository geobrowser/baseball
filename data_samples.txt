================================================================================
DATA OVERLAP & RELATIONSHIPS
================================================================================

Key joins between datasets:

  players.retrosheet_id  <-->  rosters.player_id
  players.retrosheet_id  <-->  batting/pitching/fielding.id
  players.retrosheet_id  <-->  plays.batter / plays.pitcher
  players.retrosheet_id  <-->  gamelogs.*_pitcher_id / *_manager_id / *_umpire_id
  players.retrosheet_id  <-->  ejections.ejected_id / ejections.umpire_id
  players.retrosheet_id  <-->  allplayers.id
  players.retrosheet_id  <-->  gameinfo.wp / gameinfo.lp / gameinfo.umphome / etc.

  teams.retrosheet_id    <-->  rosters.team_id
  teams.retrosheet_id    <-->  gamelogs.visiting_team / gamelogs.home_team
  teams.retrosheet_id    <-->  batting/pitching/fielding.team
  teams.retrosheet_id    <-->  schedules.visiting_team / schedules.home_team

  ballparks.retrosheet_id <--> gamelogs.park_id
  ballparks.retrosheet_id <--> gameinfo.site
  ballparks.retrosheet_id <--> plays.site

  Game IDs link:
    gamelogs (by date+teams)  <-->  batting/pitching/fielding.gid
    gameinfo.gid              <-->  batting/pitching/fielding.gid
    plays.gid                 <-->  batting/pitching/fielding.gid
    ejections.game_id         <-->  gamelogs (by date+teams)

Overlapping data between files:
  - gamelogs + gameinfo both describe games — gamelogs has team totals,
    gameinfo has weather/umpires/conditions. Join on game ID.
  - rosters + allplayers both track player-team-season — allplayers adds
    per-position game counts, rosters has primary position.
  - schedules overlaps with gamelogs but adds postponement/makeup info
    and extends into future seasons (through 2026).
  - batting + pitching + fielding can be summed to match gamelog team totals.
